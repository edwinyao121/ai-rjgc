平台定位

不是增加一个聊天入口，而是建立可治理的智能研发运行机制。

平台将需求、任务、规则、上下文、执行、审查和知识连接起来，避免智能体以脱离项目现实的方式高速产出。

核心变化
从“Agent 说已经完成”，转向“需求、代码、验证、证据和人工结论共同证明完成”。

公共底座

三层分工，各自掌握正确的事实与责任。

云端掌握权威状态与治理规则，本地掌握真实工程环境，事实与证据层让审查结论可回溯、可失效、可复用。

云端不替代本地研发

云端不直接修改工作区，不替代本地内网验证，也不代替研发人员作出具体实现判断。

云端负责目标、边界、规则与阶段决策

本地不绕开团队治理

本地不得自行修改确认需求、跳过硬门禁、接受高风险例外或发布未经审核的知识。

本地负责执行、验证、工程判断与升级
Trace记录发生过的交互、工具、命令与文件变化。
工程事实提取可核对的代码、测试、构建与版本状态。
Evidence将事实绑定到具体结论、版本和有效性。
审查结论由规则和责任人决定通过、退回或风险接受。

决定权与升级矩阵

Agent 和云端可以整理事实、生成候选与执行已授权工作，但不拥有需求裁决、风险接受或正式放行权。

事项Agent 或平台可做必须确认的责任人确认后的结果
需求、验收与风险接受结构化需求、识别冲突、生成验收候选。业务负责人；涉及风险接受时同步技术负责人。Requirement 与验收基线生效，Task 可进入规划。
接口、数据、安全、权限与跨模块变更定位影响、生成方案和验证建议。技术负责人或代码 Owner。按高风险处理；原执行包失效并重新规划。
测试归因与候选补丁执行测试、提出归因与最小补丁。研发人员；质量负责人审查质量风险。进入回归、退回或终止，不以 Agent 自述作为结论。
交付、回滚与例外放行汇总 Evidence、剩余风险和回滚条件。交付批准人；业务负责人确认风险接受。形成 Baseline、退回整改、暂停或终止记录。

受控自动修复仅适用于低风险、预授权目录、正确性明确、可回滚并可执行回归的变更。删除测试、降低断言、绕过权限、修改公共契约、数据模型或任务外文件始终禁止自动执行。

数据分级与上报边界

上报策略由项目管理员与安全负责人配置，本地先执行脱敏和策略检查。完整交互、完整仓库或原始敏感数据默认不上报。

级别可上报内容使用条件留存与访问
基础级Task 与 Run 状态、工具类型、文件摘要、哈希、门禁结果和 Artifact 元数据。默认级别。按项目留存策略自动到期；项目审查角色可访问。
审查级必要 Diff、关键命令输出、脱敏片段和关联 Evidence。审查需要且策略允许。限定审查范围与有效期，访问和删除均留审计记录。
全量级完整交互、详细工具结果或文件变化。安全负责人书面授权，明确对象、用途、范围和期限。仅授权人员访问，到期删除或重新审批。

密钥、令牌、个人敏感信息、受监管数据和不允许出域的内容不得因“审查需要”自动突破策略；原始数据与完整制品优先保留在本地或既有制品库，只上报引用与哈希。

外部系统与权威来源

Harness 管理协同状态、Trace、Evidence 和 Review Task，不取代已存在工程系统的权威记录。

代码、构建与制品Git、CI/CD 与制品库中的 commit、构建结果和制品摘要。不可变引用、Diff 摘要、门禁结果和 Evidence 索引。不以平台数据库替代源码、制品或构建系统。
身份、密钥与部署环境既有 IAM、密钥管理和部署平台。策略引用、授权结果、交付决定和环境验证 Evidence。首期不托管密钥，不直接执行生产发布。

统一研发闭环

从需求确认到知识回供，一条受控路径贯穿所有场景。

平台将业务目标、真实工程执行、Evidence 审查和团队知识沉淀连接为同一生命周期。四个场景在这条路径的不同阶段组合能力，而不重复建设治理机制。

云端治理本地执行事实与 Evidence人工决策
  1. 01业务负责人

    需求与验收确认

    云端整理目标、范围、规则、非目标范围与歧义；业务负责人确认验收，技术负责人确认风险接受边界。

    产物：已确认 Requirement 与验收基线

  2. 02云端治理

    Task 规划与风险分级

    云端结合研发基线拆分 Task、识别依赖和授权范围；标准风险以上方案由责任人确认后才可下发。

    产物：已确认 Task、风险策略与 Review 要求

  3. 03云端治理

    执行包下发

    将目标、约束、上下文、工具权限和验证命令以可校验版本交给本地执行现场。

    产物：Task Package 与 Context Package

  4. 04本地执行

    Harness Run 本地执行

    在真实仓库、依赖与环境中运行授权工作流。上下文失效、权限变化、环境不可用、越界或高风险时必须暂停并升级。

    产物：Harness Run、过程 Trace、异常与暂停原因

  5. 05本地执行

    Artifact 与本地验证

    形成代码、测试、文档、构建或制品等 Artifact，并在真实条件下执行必要验证。

    产物：Artifact、Diff 与验证结果

  6. 06事实与 Evidence

    Trace 到 Evidence 转换

    从过程与产物提取可核对的 Engineering Fact，将事实绑定到结论、版本和有效性条件。

    产物：Engineering Fact 与 Evidence

  7. 07云端治理

    云端预审与 Review Task

    汇总实际差异、验收覆盖、风险和 Evidence，路由需要人工判断的问题与复审材料。

    产物：Review Task 与问题清单

  8. 08人工决策

    人工决策、整改与复审

    责任人决定通过、退回、有条件放行、风险接受、暂停或终止。需求、契约、数据或授权变化时使原执行包失效并重新规划。

    产物：审查结论、整改要求或终止记录

  9. 09云端治理

    Baseline 发布与知识候选审核

    将已确认的软件、文档、制品与 Evidence 固化为共同 Baseline；知识仅生成候选，须单独审核通用性、范围和失效条件后发布。

    产物：Baseline 与待审核 Knowledge Candidate

重新规划：从变化或阻塞回到需求与任务

需求、公共契约、数据模型、安全规则、授权或环境发生重大变化时，暂停当前 Run，使 Task Package 与 Context Package 失效后重新确认。

退回整改：从人工审查回到本地执行

问题与 Evidence 关联到原 Task。研发人员在授权范围内修订后，新建 Harness Run 并重新进入验证和预审。

知识回供：从已批准经验回到后续规划

经过人工审核的 Knowledge Entry 更新研发基线，并在后续 Task Package 与 Context Package 中按适用范围复用。

一

快速生成与云就绪交付

从业务需求到可运行、可验证、可回滚的交付单元。

›

理解与分级

该场景把需求、生成、验证、修复和交付组织为连续闭环。工程等级决定成果深度，风险等级决定门禁强度，交付方式决定最终产物。

  • 验证原型可使用 Mock，但必须列出非生产项
  • 轻量可用必须可启动并提供基础恢复说明
  • 生产级必须绑定需求、测试、配置和交付 Evidence

关键流程与产物

  1. 澄清需求并判定工作类型、成熟度、工程与风险等级
  2. 装配项目规范、组件、基础镜像和交付约束
  3. 确认计划后生成代码、测试、配置和部署资源
  4. 构建、启动、测试，失败后有限修复或人工接管
  5. 形成镜像 digest、资源清单、运行说明和交付 Baseline

功能分组

  • 执行策略、计划与风险强制升级
  • Dockerfile、镜像、配置模板和健康检查
  • 环境预检、部署验证、回滚与离线依赖分析
  • 代码、镜像、资源和文档的版本绑定

人工卡点与红线

生产级、标准风险以上、存量变更、数据库或公共接口变更、对外交付与离线交付必须确认计划。

硬门禁失败不得标记可交付。首期只验证容器化与云就绪交付基线、Evidence 和回滚条件，不执行复杂生产发布或客户现场离线部署。

二

团队规范化智能开发

将团队隐性经验转化为可执行、可审查、可演进的研发基线。

›

理解与目标

核心不是给每个人配一个 AI，而是让团队在同一套项目基线、任务边界和人工责任下可靠使用智能体。

  • 规范可执行
  • 任务可控制
  • 过程可审查
  • 经验可演进

关键流程与产物

  1. 建立包含规则、Agent、门禁和 Owner 的研发基线
  2. 结构化需求，拆分 Task 并确认依赖和风险
  3. 下发 Task Package、Context Package 与验证清单
  4. 本地在隔离工作区受控研发并持续采集 Trace
  5. 云端预审、人工决策、整改复审和知识回流

功能分组

  • 研发基线、Agent、工具和权限配置
  • 需求、验收、依赖、冲突范围与责任管理
  • 本地 Run、分支、过程采集和越界检测
  • 审查单、整改闭环和知识发布

人工卡点与红线

需求确认、任务规划、高风险方案、阶段成果、合并交付和知识发布都保留清晰责任人。

低风险任务应保持轻量。公共契约、共享资产、数据、安全和架构变化必须先确认，重大范围变化使原执行包失效。

三

与智能编码一致的软件工程文档

让文档成为编码约束、审查载体和软件共同基线的一部分。

›

理解与一致性

文档既约束编码，也随编码演化，并成为审查和共同 Baseline 的组成部分。关键结论必须优先由工程事实和 Evidence 支撑。

  • 需求、设计、接口与数据一致性
  • 测试、状态、过程与版本一致性

关键流程与产物

  1. 确定 Document Package、模板和章节责任
  2. 将已确认文档裁剪进 Context Package
  3. 采集本地代码、测试、构建和人工事实
  4. 定位受影响章节并生成增量建议
  5. 双向校核、人工审核并形成共同 Baseline

功能分组

  • 文档包、章节状态、审核和归档管理
  • 章节级影响分析、来源标注和差异合并
  • 追溯矩阵、Evidence 索引和一致性报告
  • 基线偏离检测和知识候选提取

人工卡点与红线

需求方案、文档审核、基线批准和知识发布需要人工决策。系统只生成候选更新，不直接发布正式结论。

代码现状不能自动反向修改已批准的需求或设计。人工已审核、已锁定内容不得静默覆盖。

四

智能化软件功能测试与修复

以正确性依据、失败归因、受控修复和影响回归形成可信质量闭环。

›

理解与正确性依据

场景要解决的是“测得准、定位准、修得对”。需求、验收、业务规则、契约、页面行为、Diff、测试资产和环境版本共同构成正确性依据。

没有明确依据时，测试假设必须被标注，不能被当作正式通过标准。

关键流程与产物

  1. 确认目标、必测项、范围和代码基线
  2. 检查本地环境、依赖与测试数据
  3. 生成并执行接口、UI、端到端等真实测试
  4. 区分需求、数据、环境、契约和代码失败
  5. 授权修复、原问题验证、影响回归和云端审查

功能分组

  • 需求到测试场景和断言来源的覆盖管理
  • 多方式执行、日志截图和环境健康检查
  • 候选根因、可信度、补丁与影响分析
  • 回归集推荐、未覆盖风险和证据包

人工卡点与红线

研发人员确认归因和补丁，质量负责人审查质量风险。受控自动修复仅限低风险、预授权目录、正确性明确、可回滚并可执行回归的最小变更。

需求冲突、范围扩大、跳过必测项、公共契约、数据权限、跨模块影响和风险接受必须升级。不得删除测试、降低断言、绕过权限校验；环境、数据和非确定性失败不得直接判为代码缺陷。

统一功能地图

共性能力只建设一次，场景能力按需组合。

每一个功能模块都有清晰的接口和责任范围，避免四个场景分别建设任务、Trace、审查与知识能力。

治理与供给

把正确的约束、上下文和责任交到执行现场。

这一层维护项目的权威规则，并把已确认的目标、边界与可执行上下文有版本地供给给本地研发。

项目治理与研发基线

职责：将项目规则、角色、工具权限和门禁管理为可发布、可回退的研发基线，不替代本地工程判断。

关键能力
  • 编码、测试、安全与交付规则版本化
  • 角色权限、代码 Owner 与审批路由配置
  • Agent、Skill、工具白名单和门禁策略装配
  • 基线发布、适用范围校验与回退
输入
项目目标、技术标准、安全要求和团队责任。
输出
研发基线、门禁策略、权限矩阵和工作流版本。

关联对象：Baseline、Context Package、Knowledge Entry。

服务场景：全部场景的控制平面，为后续任务和本地执行提供统一约束。

需求与任务总控

职责：把业务目标变为可执行、可审查的任务单元，明确完成标准、依赖关系、风险和需要人工决策的时点。

关键能力
  • 需求结构化、缺失项和冲突项识别
  • 验收项、范围边界和非目标范围确认
  • Task 拆分、依赖图、共享资产冲突与责任分派
  • 风险分级、门禁配置和阶段状态管理
输入
原始需求、已有代码、业务规则和项目基线。
输出
Requirement、Task、验收清单、风险结论与审查事项。

关联对象：Requirement、Task、Task Package、Review Task。

服务场景：全部场景的治理入口，决定每次执行的目标、范围和升级条件。

上下文与执行供给

职责：将任务所需的规则、事实、工具和验证要求裁剪成可校验的执行包，防止本地 Agent 依据过期或无关信息工作。

关键能力
  • 需求、设计、知识和规则的来源选择与冲突提示
  • 目标、授权目录、依赖、暂停条件和完成定义下发
  • Agent、Skill、工具权限与验证命令按任务装配
  • 版本、适用范围、失效条件和本地使用记录校验
输入
Task、研发基线、知识条目和工程约束。
输出
Task Package、Context Package 与验证清单。

关联对象：Task Package、Context Package、Baseline。

服务场景：全部场景的云边交接面，连接云端规划与本地真实执行。

知识演进

职责：将经验证的审查结论和工程经验沉淀为可复用知识，避免把 Agent 自述或单次结论直接变成团队规则。

关键能力
  • 从评审、门禁失败和优秀实践提取候选
  • 人工审核通用性、适用范围与发布责任
  • 版本替代、失效、回退和使用效果跟踪
  • 将已发布知识回供给后续 Context Package
输入
Evidence、Review Task、复盘记录和使用反馈。
输出
已审核知识条目、适用规则和基线更新建议。

关联对象：Knowledge Entry、Evidence、Baseline。

服务场景：全部场景持续复用，形成从一次交付到团队能力的反馈回路。

云边执行与可信闭环

本地完成真实工作，云端只依据可追溯事实进行治理。

这一层确保执行不脱离工程环境，过程不脱离证据，审查结论不脱离责任人。

本地智能研发运行时

职责：在真实仓库、依赖、网络和权限条件下承载一次受控研发执行，并将工程异常及时升级。

关键能力
  • 项目同步、分支或隔离工作区准备
  • 按授权范围启动 Agent、工具与验证命令
  • 越界、高风险、用户确认和失败重试的暂停升级
  • 离线缓存、顺序补传、幂等接收与完整性提示
输入
Context Package、Task Package、本地工程环境。
输出
Harness Run、Trace、Artifact、本地验证结果与异常。

关联对象：Harness Run、Artifact、Trace。

服务场景：全部场景的真实执行面，不由云端直接修改本地工作区。

Trace、工程事实与 Evidence

职责：将可采集过程转成可核对工程事实，再将事实绑定到结论、版本和有效性条件；该模块不自行作出批准结论。

关键能力
  • 交互、工具、命令、文件变化和验证结果采集
  • 本地脱敏、来源关联、完整性标记和上报策略控制
  • 从代码、测试、构建和版本中提取 Engineering Fact
  • Evidence 索引、失效条件、来源追溯和复用查询
输入
Trace、Artifact、Git Diff、测试构建和人工操作。
输出
Engineering Fact、Evidence 集合与可信度状态。

关联对象：Trace、Engineering Fact、Evidence、Artifact。

服务场景：全部场景的可信结论基础，支撑审查、基线和知识沉淀。

云端预审与人工卡点

职责：把任务目标、实际差异、风险和 Evidence 汇总为可决策审查单，并记录退回、豁免、放行与责任归属。

关键能力
  • 范围越界、验收缺口、质量风险和证据完整性预审
  • 任务摘要、关键 Diff、影响范围和剩余风险的审阅视图
  • 按角色路由人工审查、整改、复审和风险接受
  • 豁免有效期、放行条件、审查意见和阶段状态回写
输入
Task、Engineering Fact、Evidence、Artifact 与风险策略。
输出
Review Task、问题清单、审查结论和阶段推进记录。

关联对象：Review Task、Evidence、Task、Baseline。

服务场景：全部场景的人工责任面。Agent 可以归纳材料，但不能替代人员批准、豁免或接受风险。

场景闭环能力

在同一治理与证据底座上，组合三类高价值研发工作流。

三项能力不重复建设任务、运行时或审查机制，而是在公共对象和统一门禁上完成各自的业务闭环。

工程文档与共同基线

职责：让需求、设计、接口、测试与代码相互校核，形成可审查的软件工程文档和共同 Baseline。

关键能力
  • Document Package、章节状态与责任分配
  • 章节级影响分析、增量候选和来源标注
  • 追溯矩阵、双向校核与一致性报告
  • 基线偏离检测、审批归档与锁定保护
输入
需求设计、代码测试、工程事实和 Evidence。
输出
文档增量、校核报告、Document Package 和共同基线。

关联对象：Artifact、Evidence、Baseline、Context Package。

服务场景：以文档一致性为主，并为生成交付和测试结论提供共同依据。

生成与交付编排

职责：将受控需求转为可运行、可验证、可回滚的交付单元，并使代码、配置、镜像和交付说明保持同一版本关系。

关键能力
  • 工程等级、风险等级和交付方式判定
  • 代码、测试、配置、部署资源和运行说明生成
  • 构建、镜像、健康检查、环境验证和有限修复
  • 回滚条件、离线依赖分析和交付基线装配
输入
Requirement、执行包、组件规范和目标环境约束。
输出
代码与配置 Artifact、镜像摘要、交付 Evidence 和 Baseline。

关联对象：Artifact、Evidence、Baseline、Review Task。

服务场景：快速生成与云就绪交付为主，复用文档和测试能力完成可交付验证。

智能测试与修复

职责：围绕明确正确性依据执行真实测试、归因失败、生成受控补丁并验证影响回归。

关键能力
  • 需求到测试场景、断言来源和覆盖缺口管理
  • 接口、UI、端到端执行与环境健康检查
  • 失败归因、补丁授权、原问题验证和影响回归
  • 质量结论、未覆盖风险与证据包生成
输入
正确性依据、代码 Diff、测试资产和目标环境。
输出
测试结果、候选补丁、回归结论和质量 Evidence。

关联对象：Harness Run、Artifact、Evidence、Review Task。

服务场景：智能测试与修复为主，并为交付放行和文档校核提供验证事实。

建设重点

第一阶段只证明一件事：一条真实变更能够受控闭环。

先以一个已有代码仓库的中等复杂度需求变更验证平台差异化能力，再逐步扩展至智能测试修复和容器化交付。

存量项目需求变更

第一阶段不追求复杂多 Agent 调度、完整 Kubernetes 管理或无人值守发布。至少选择 3 个同类中等复杂度需求变更，验证云端规划、本地研发、证据审查、文档更新与知识沉淀可以稳定衔接。
