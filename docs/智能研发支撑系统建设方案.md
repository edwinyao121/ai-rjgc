# 智能研发支撑系统建设方案

---

## 一、系统概述

### 1.1 建设背景

随着企业软件研发规模持续扩大，传统研发管理模式面临多重挑战：项目信息分散、研发流程缺乏统一编排、质量管控依赖人工经验、AI 能力难以体系化复用。为解决上述问题，本系统以"**可视、可信、可控**"为核心产品理念，构建覆盖软件研制全生命周期的智能研发支撑平台。

### 1.2 建设目标

建设一套以 AI 智能体为驱动核心的研发支撑系统，实现：

- **流程自动化**：从需求分析到制品交付的八阶段标准流程由 AI 智能编排与执行
- **质量门禁化**：关键质量节点设置自动化门禁检查，阻断不合规产出物
- **决策人机协同**：AI 自动执行常规任务，关键节点由人工评审决策
- **全链路可追溯**：从需求到制品的完整证据链，满足安全审计与合规要求
- **全局可观测**：管理者可实时掌握多项目研发状态、效能指标与风险告警

### 1.3 产品理念

| 理念 | 含义 |
|------|------|
| **可视** | 全流程状态实时可视化，研发活动透明可观察 |
| **可信** | 门禁自动检查 + 证据链管理，产出质量可验证 |
| **可控** | 人工干预机制 + 规则动态配置，研发过程可管控 |

## 二、系统架构

### 2.1 总体架构

系统采用多文件 SPA 架构，由数据层、路由层、业务模块层三层组成：

```
┌─────────────────────────────────────────────────────────┐
│                      展示层 (index.html + styles.css)     │
├─────────────────────────────────────────────────────────┤
│                    路由与导航层 (router.js)                │
├──────────┬──────────┬──────────┬─────────────────────────┤
│ 工作台    │ 项目空间  │ 任务看板  │  流水线  │ 评审 │ 追溯  │
│dashboard │projects  │ kanban   │pipeline │reviews│gates │
├──────────┴──────────┴──────────┴─────────────────────────┤
│                 业务模块层 (各页面 JS 模块)                 │
├─────────────────────────────────────────────────────────┤
│                   数据与状态层 (data.js)                   │
│              全局 state 对象 + 工具函数 + 静态数据            │
└─────────────────────────────────────────────────────────┘
```

### 2.2 上下文层级

系统支持两级上下文，通过 `context.level` 区分：

| 层级 | 说明 | 包含页面 |
|------|------|----------|
| **全局级** | 平台管理视角，跨项目操作 | 工作台、项目空间、评审中心、智能体管理、技能市场、门禁配置、规范约束 |
| **项目级** | 单项目内部操作 | 任务看板、流水线监控、研发追溯、项目评审、项目智能体、项目技能库、项目规范、研制总结 |

进入项目后，侧边栏自动切换为项目内导航菜单，实现空间隔离。

## 三、核心业务模块

### 模块一：项目空间管理

**业务定位**：提供多项目并行研发的统一管理入口，实现项目信息集中化管理。

**核心能力**：

| 能力 | 说明 |
|------|------|
| 项目全生命周期管理 | 创建、运行、评审、阻塞、完成等状态全覆盖 |
| 项目信息维护 | 名称、描述、关联代码仓库、成员管理 |
| 进度可视化 | 阶段完成度进度条、成员参与度展示 |
| 多项目切换 | 项目卡片网格 + 快速进入项目看板 |

**数据实体**：项目（Project）、成员（Member）、代码仓库（Repository）

---

### 模块二：任务看板与生命周期管理

**业务定位**：为研发团队提供结构化的任务管理能力，实现任务状态的可视化流转与管控。

**核心能力**：

| 能力 | 说明 |
|------|------|
| 任务创建 | 手动创建（标题、描述、类型、优先级、工时、负责人） |
| AI 智能创建 | 基于需求文档或会议纪要，AI 自动分析并生成候选任务列表，支持批量创建 |
| 五阶段状态管控 | 待办 → 规划中 → 执行中 → 待评审 → 已完成 |
| 状态迁移校验 | 系统强制执行合法状态流转规则，防止非法跳转 |
| 拖拽式操作 | 原生 Drag & Drop 交互，直观便捷 |

**状态流转规则**：

```
待办 ──→ 规划中 ──→ 执行中 ──→ 待评审 ──→ 已完成
 ↑         │                      │         │
 └─────────┘                      └─────────┘
```

**数据实体**：任务（Task）、任务状态（TaskStatus）、任务类型（Feature / Enhancement / Bug / Refactor）

---

### 模块三：AI 智能流水线引擎

**业务定位**：系统核心引擎，实现从需求到制品的全流程自动化编排与执行。

**核心能力**：

| 能力 | 说明 |
|------|------|
| 流水线智能规划 | 根据任务类型自动生成执行阶段序列（Feature 8 阶段 / Refactor 6 阶段 / 其他 5 阶段） |
| 标准八阶段流程 | 需求分析 → 需求拆解 → 方案设计 → 代码生成 → 代码审查 → 单元测试 → UI 测试 → 生成制品 |
| 多 Agent 协作 | 阶段间产出物自动传递，支持多 Agent 并行协作 |
| 流水线可视化 | 节点状态、门禁检查结果、阶段进度、Agent 通信消息实时展示 |
| 智能回退修复 | 门禁阻断时自动回退到代码生成阶段修复后重新执行 |
| 完美演示模式 | 自动按序执行全部阶段，展示完整无阻断的流水线流程 |

**八阶段标准流程**：

| 阶段 | 负责 Agent | 核心产出物 |
|------|-----------|-----------|
| 需求分析 | 需求分析 Agent | 需求分析报告 |
| 需求拆解 | 需求拆解 Agent | 拆解后的需求条目 |
| 方案设计 | 方案设计 Agent + 人工评审 | 架构设计方案 |
| 代码生成 | 代码生成 Agent | 源代码文件 |
| 代码审查 | 代码审查 Agent + 人工评审 | 审查报告 |
| 单元测试 | 单元测试 Agent | 测试用例与覆盖率报告 |
| UI 测试 | UI 测试 Agent | 测试证据截图与报告 |
| 生成制品 | 制品生成 Agent | 容器镜像 |

**数据实体**：流水线（Pipeline）、阶段（Stage）、阶段智能体（StageAgent）、智能体通信（AgentComm）

---

### 模块四：质量门禁管控系统

**业务定位**：在研发流程关键节点设置自动化质量检查，确保产出物符合质量标准。

**核心能力**：

| 能力 | 说明 |
|------|------|
| 六大类门禁规则 | 架构合规、安全漏洞、编码规范、测试覆盖率、技术债务、制品验收 |
| 门禁动态配置 | 支持启用/禁用单条规则、调整通过阈值（0-100%） |
| 阻断与警告 | 强控模式阻断不合格产出物，警告模式提示风险 |
| 阻断处理决策 | 门禁阻断时提供三种处理路径：Agent 自动修复、人工跳过、取消 |
| 证据链管理 | 每条门禁记录检查结果描述和证据文件 |

**门禁类型**：

| 类型 | 行为 |
|------|------|
| `pass` | 门禁通过，允许进入下一阶段 |
| `warn` | 门禁警告，允许继续但记录风险 |
| `fail` | 门禁阻断，必须修复后才能继续 |

**数据实体**：门禁定义（GateDef）、门禁结果（GateResult）、门禁配置（GateConfig）、门禁证据（GateEvidence）

---

### 模块五：人工评审与决策支持

**业务定位**：在关键研发节点引入人工把关机制，实现 AI 执行与人类决策的有机结合。

**核心能力**：

| 能力 | 说明 |
|------|------|
| 评审自动触发 | 方案设计、代码审查阶段执行完毕后自动创建评审任务 |
| 评审工作流 | 待评审 → 已通过 / 需修改 / 已驳回 |
| 评审意见管理 | 支持提交文字评审意见，记录决策过程 |
| 流水线联动 | 全部评审通过 + 门禁通过后自动推进到下一阶段 |
| 冲突评审决策 | 针对语义冲突场景，提供 AI 分析建议和两种解决方案供人工决策 |

**评审状态**：

| 状态 | 说明 |
|------|------|
| 待评审 | 评审任务已创建，等待评审人处理 |
| 已通过 | 评审通过，流水线继续推进 |
| 需修改 | 评审发现问题，需要修改后重新提交 |
| 已驳回 | 评审驳回，需要重新执行 |

**数据实体**：评审（Review）、评审决策（ReviewDecision）、冲突决议（ConflictResolution）

---

### 模块六：智能体与技能资产管理

**业务定位**：构建 AI 能力的统一管理体系，实现智能体和技能的市场化运营与复用。

**核心能力**：

| 能力 | 说明 |
|------|------|
| 智能体全生命周期 | 注册、配置、运行、删除，支持上传部署包 |
| 技能市场 | 技能版本管理、调用统计、启停控制、标签分类 |
| 阶段能力匹配 | 按阶段自动分配最优 Agent 执行 |
| 多 Agent 协作 | 需求分析、方案设计等阶段支持多 Agent 并行协作 |
| 项目级定制 | 项目可从平台选择预置智能体，也可创建自定义智能体 |

**智能体配置项**：

| 配置 | 说明 |
|------|------|
| 名称 | 智能体标识名称 |
| 负责阶段 | 关联的研发阶段（12 个可选阶段） |
| 头像图标 | 可视化标识 |
| 功能描述 | 能力说明 |
| 部署包 | 支持 .zip / .tar.gz / .rar / .7z / .gz 格式 |

**数据实体**：智能体（Agent）、技能（Skill）、智能体包（AgentPackage）、技能包（SkillPackage）

---

### 模块七：研发追溯与审计合规

**业务定位**：建立从需求到制品的完整追溯链路，满足安全审计与合规要求。

**核心能力**：

| 能力 | 说明 |
|------|------|
| 审计报告生成 | 按任务、按项目分组展示全量门禁检查结果 |
| 活动日志记录 | Agent 工作、智能体通信、人工操作、门禁检查全量记录 |
| 证据链管理 | 检查结果描述 + 证据文件关联，形成完整证据链 |
| 追溯链路可视化 | 从需求分析到生成制品的全链路追溯，阻断阶段红色高亮 |
| 合规统计 | 审计任务数、总通过率、阻断任务数等关键指标 |

**审计报告内容**：

| 维度 | 说明 |
|------|------|
| 任务信息 | 标题、编号、类型、优先级、预估工时、项目名、需求来源 |
| 检查信息 | 检查时间、审计员、阻断数、通过率 |
| 阶段详情 | 每阶段的门禁检查结果、通过数/总数、证据文件 |
| 审计结论 | 阶段完成数、阻断数、总通过率、追溯链路图 |

**数据实体**：审计报告（AuditReport）、活动日志（ActivityLog）、追溯链路（TraceChain）

---

### 模块八：全局监控与工作台

**业务定位**：为管理者提供全局视角的效能监控与风险预警能力。

**核心能力**：

| 能力 | 说明 |
|------|------|
| 全局效能仪表盘 | Agent 代码生成量、活跃调用数、门禁通过率、需求可追溯性 |
| 待办事项中心 | 待处理评审提醒、门禁阻断任务提醒 |
| 三维度价值呈现 | 可视（实时动态）、可信（质量指标）、可控（干预统计） |
| 高危节点追踪 | 阻断任务列表 + 一键干预跳转 |
| 活跃项目概览 | 项目进度、状态、参与人数快速一览 |
| 定时检测任务 | 代码行数检测、AI 代码比例检测、文档规范检查 |

**可视-可信-可控三维指标**：

| 维度 | 核心指标 |
|------|----------|
| **可视** | Agent 代码生成行数、智能体调用次数、实时动态 Feed |
| **可信** | 全局门禁通过率、需求可追溯性、六大质量门禁健康度 |
| **可控** | 人工干预次数、已通过架构评审数、高危节点追踪 |

**数据实体**：工作台（Dashboard）、时间线（Timeline）、效能指标（Metric）、定时任务（ScheduledTask）

## 四、全局规范体系

系统支持两级规范配置，约束 AI 智能体的执行行为：

### 4.1 平台级规范

面向全局生效，涵盖五大类：

| 规范类别 | 说明 |
|----------|------|
| 工程规范 | 通用工程标准与最佳实践 |
| 安全规范 | 安全编码与漏洞防护要求 |
| 协作规范 | 团队协作与版本管理约定 |
| 测试规范 | 测试覆盖率与质量标准 |
| 发布规范 | 制品发布与部署要求 |

每类规范支持启用/禁用开关、文本编辑、模板预设（如 Spring Boot、Go Gin、NestJS 等）、AI 优化生成。

### 4.2 项目级规范

在平台级规范基础上，增加三类项目专用规范：

| 规范类别 | 说明 |
|----------|------|
| 架构与技术栈 | 项目特定的框架选型与架构约束 |
| 编码与格式 | 代码风格与格式化规则 |
| 业务领域 | 业务特定的领域知识与约束 |

项目级规范支持 Onboarding Tour 新手引导，帮助用户快速上手配置。

## 五、模块关联关系

```
┌─────────────────────────────────────────────────────────┐
│               全局监控与工作台 (模块八)                    │
│          全局概览 / 待办中心 / 效能指标 / 风险预警          │
└────────────────────────┬────────────────────────────────┘
                         │
           ┌─────────────┼─────────────┐
           ▼             ▼             ▼
    ┌──────────┐  ┌──────────────┐  ┌──────────┐
    │ 项目空间  │  │ 智能体与技能  │  │ 门禁规则  │
    │ 管理     │  │ 资产管理     │  │ 配置      │
    │ (模块一) │  │ (模块六)     │  │ (模块四)  │
    └────┬─────┘  └──────┬───────┘  └────┬─────┘
         │               │               │
         ▼               ▼               ▼
    ┌─────────────────────────────────────────────┐
    │          AI 智能流水线引擎 (模块三)           │
    │      智能规划 / 阶段编排 / Agent 协作         │
    └─────────────────────────────────────────────┘
                         │
           ┌─────────────┼─────────────┐
           ▼             ▼             ▼
    ┌──────────┐  ┌──────────┐  ┌──────────────┐
    │ 任务看板  │  │ 质量门禁  │  │ 人工评审与    │
    │ 生命周期  │  │ 管控系统  │  │ 决策支持      │
    │ (模块二) │  │ (模块四)  │  │ (模块五)     │
    └──────────┘  └────┬─────┘  └──────────────┘
                       │
                       ▼
    ┌─────────────────────────────────────────────┐
    │       研发追溯与审计合规 (模块七)             │
    │     审计报告 / 证据链 / 追溯链路 / 合规检查    │
    └─────────────────────────────────────────────┘
```

**关键依赖关系**：

1. **项目管理 → 任务管理**：项目是任务的容器，项目进度由任务完成度驱动
2. **流水线引擎 → 门禁系统**：流水线每阶段执行时触发门禁检查，门禁阻断暂停流水线
3. **流水线引擎 → 评审系统**：关键阶段执行完毕自动触发人工评审，评审通过后自动推进
4. **流水线引擎 → 智能体管理**：每阶段由对应 Agent 执行，Agent 能力来自技能资产
5. **门禁系统 → 审计追溯**：门禁结果形成审计证据链，支撑全链路可追溯
6. **工作台 → 所有模块**：汇聚各模块待办、风险、指标，提供统一管理视图

## 六、设计原则

| 原则 | 说明 |
|------|------|
| **Agent 驱动** | 以 AI 智能体为核心执行单元，实现研发流程的自动化编排与执行 |
| **门禁强控** | 关键质量节点设置自动化门禁检查，阻断不合规产出物流入下一阶段 |
| **人机协同** | AI 自动执行常规任务，关键节点由人工评审决策，重大冲突由人工行政干预 |
| **全链路追溯** | 从需求到制品的完整证据链，满足安全审计与合规要求 |
| **可观测性** | 全流程状态实时可视化，管理者可随时掌握研发进度与风险 |
