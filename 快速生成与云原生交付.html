01

Understanding

先看理解：快速生成和云原生交付解决什么

本专题不是单纯讨论代码生成，也不是单纯讨论容器部署，而是打通“应用如何更快形成”与“应用如何稳定交出去”两个连续问题。

一句话理解
快速生成解决“应用如何更快形成”，云原生交付解决“应用如何稳定交出去”，Harness 解决“生成和交付过程如何可信、可控、可追溯”。
01

快速生成

承接自然语言需求和项目规范，快速形成可验证、可运行、可继续演进的应用成果。

  • 生成页面、业务逻辑、接口和数据结构。
  • 同步生成测试、配置和工程资源。
  • 通过真实构建、启动和冒烟验证发现问题。
  • 将失败证据反馈给智能体，形成有限修复闭环。
02

云原生交付

把生成结果转化为可构建、可部署、可验证、可回滚、可追溯的交付单元。

  • 形成镜像构建配置、镜像版本和摘要。
  • 生成 Kubernetes 资源、配置模板和健康检查。
  • 执行环境预检、部署验证、冒烟和回滚验证。
  • 支持在线发布和高约束离线交付。
H

Harness 控制底座

连接需求、智能体、工具链和交付环境，以计划、门禁、审批和证据保障全过程可信。

  • 先形成执行计划，再组织智能体执行。
  • 控制上下文、工作区、工具权限和资源预算。
  • 按风险等级匹配门禁、审批和证据强度。
  • 支持暂停、修复、人工接管、回退和追溯。

快速生成不是一种固定深度

工程等级决定“生成到什么程度”，风险等级决定“验证和控制到什么程度”。两者共同形成执行策略，但不改变专题主线。

工程等级：决定前半段生成深度
验证原型快速验证流程、页面和需求方向
轻量可用快速形成真实可用的小型应用
生产级形成符合规范、测试和运维要求的正式应用
×
风险等级：决定后半段控制强度
低风险启动、冒烟、敏感配置与恢复检查
标准风险测试、静态检查、安全检查与部署验证
高风险严格审批、扫描、回滚验证与完整证据链

建设后的变化

  • 从“人工搭工程、人工补测试、人工补部署资源”转为协同生成。
  • 从“代码生成完成”转为“应用构建、运行和验证完成”。
  • 从“把程序包交给运维”转为“交付可被平台接管的应用单元”。
  • 从失败靠人排查转为失败可定位、可反馈、可修复。

必须守住的边界

  • 原型不能直接包装成生产系统。
  • AI 不能自行声明测试、部署和验收成功。
  • 高风险条件不得通过降低等级绕过硬门禁。
  • 离线包必须来自已验证版本基线，而不是开发目录。
审

领导审阅时重点看什么

是否真正缩短从需求到可运行应用的路径；是否同步形成镜像、部署资源和验证结果；是否能根据工程等级和风险等级控制快与稳之间的平衡。

02

Process

再看流程：从业务需求到云原生交付

总体流程先沿一条主线推进，再由工程等级控制生成深度、由风险等级控制门禁和审批强度，最终形成在线或离线交付结果。

总体业务闭环

快速生成负责前半段“把需求变成应用”，云原生交付负责后半段“把应用变成可稳定运行和交付的应用单元”。

01业务需求输入自然语言需求、项目规范、代码上下文、部署约束
→
02需求理解与目标判断识别需求成熟度、工程等级、风险等级与交付目标
→
03快速生成代码、测试、配置、数据结构和部署资源协同生成
→
04自动验证与反馈修复构建、启动、测试、扫描、失败诊断和有限修复
→
05分级门禁与人工评审按风险执行轻量、标准或严格门禁
→
06云原生交付物形成镜像、Kubernetes 资源、配置、脚本、回滚和证据
→
07在线发布或离线交付目标环境验证、版本锁定、交付归档

工程等级改变“快速生成”的前半段

不同等级共享需求理解和计划形成，但生成内容、验证深度和输出结果不同。

工程等级 01

验证原型

低成本验证需求方向

生成页面、交互、Mock 数据和临时接口。
验证关键流程与交互，记录反馈和待澄清项。
输出：可演示原型、非生产项清单、生产化输入。
工程等级 02

轻量可用

快速得到真实可用小应用

生成完整核心流程、基础配置和错误处理。
执行构建、启动、冒烟及数据恢复检查。
输出：本地、单机或容器可运行应用及基础证据。
工程等级 03

生产级

形成正式业务应用能力

生成代码、测试、配置、迁移和部署资源。
执行完整测试、安全校核、部署和回滚验证。
输出：受控版本基线、可部署产物和完整交付证据。

风险等级改变“云原生交付”的后半段

风险越高，审批、门禁、失败处理和证据要求越严格；风险等级不能用于替代工程等级。

风险等级计划与审批验证与门禁交付与证据
低风险用户确认范围和生成目标启动、核心冒烟、敏感配置、备份恢复本地/单机/简单容器，保留基础生成和验证记录
标准风险技术负责人确认计划、影响和测试策略需求覆盖、测试、静态检查、安全检查、镜像与部署验证锁定代码和镜像版本，形成结构化证据索引
高风险需求、技术、质量或交付角色分权审批安全扫描、资源校核、环境预检、回滚和完整性验证严格版本锁定、完整证据链，支持高约束在线或离线交付
验证原型 × 低风险

快速生成并验证页面与流程，输出非生产项和待澄清问题，不进入正式云原生交付。

轻量可用 × 标准风险

生成真实应用并执行标准测试、安全检查和容器部署验证，形成可追溯版本。

生产级 × 高风险 × 离线

计划审批、严格门禁、等价环境部署与回滚验证、锁定 commit/digest，再生成离线交付包。

关键规则：快速不等于降低必要约束。工程等级决定生成到什么程度，风险等级决定控制到什么程度，交付方式决定最终如何验证和交出去。高风险条件具有强制升级权。
场景目标
从明确需求到可运行应用

关键控制

  • 先锁定项目规范和技术栈。
  • 生产级或标准以上风险必须确认计划。
  • 生成完成不等于成功，必须真实构建、启动和验证。

主流程

  1. 提交业务目标、角色、核心流程、数据对象和验收线索。
  2. 判断需求成熟度、工程等级、风险与交付方式。
  3. 形成应用范围、阶段任务、验证策略和交付计划。
  4. 创建隔离工作区，生成工程骨架、代码、测试和配置。
  5. 执行构建、启动和核心流程验证。
  6. 失败则按策略有限修复；超限后人工接管。
  7. 门禁通过后形成产物版本和交付结果。
场景目标
在真实代码上下文中受控变更

关键控制

  • 必须绑定代码基线并使用独立分支或工作区。
  • 计划必须说明接口、数据、配置和回归影响。
  • 不得默认直接修改受保护分支。

主流程

  1. 提交变更需求、验收标准和目标仓库。
  2. 拉取代码基线并建立隔离工作区。
  3. 智能体读取项目规范与必要上下文，生成影响分析。
  4. 人工确认影响模块、数据、接口、配置和回滚策略。
  5. 智能体执行修改，系统记录完整文件差异。
  6. 执行受影响模块测试、回归测试和门禁。
  7. 形成变更集、提交记录或合并请求材料。
场景目标
以可复现证据证明问题已修复

关键控制

  • 无法复现时不得猜测“已修复”。
  • 优先最小范围修改并补充回归用例。
  • 修复完成必须同时满足原问题消失和相关门禁通过。

主流程

  1. 提交现象、复现步骤、日志、错误和期望结果。
  2. 确认问题可复现并保留修复前失败证据。
  3. 分析根因并生成最小修复计划。
  4. 执行修改并补充回归测试。
  5. 重复原复现步骤和相关测试。
  6. 输出根因、差异、验证证据及潜在影响。
场景目标
把原型认知转成生产级输入

关键控制

  • 原型用于验证，不用于直接上线。
  • 必须输出非生产项和未验证约束。
  • 转生产应创建新的生产级 Run，而非原地升级代码。

主流程

  1. 探索中需求进入验证原型。
  2. 记录用户反馈、待澄清项和未验证约束。
  3. 形成需求项、验收标准和非生产项清单。
  4. 将 Mock、临时接口、简化权限等转换为生产化任务。
  5. 人工确认需求版本。
  6. 基于确认后的输入创建新的生产级 Harness Run。

流程中的四个关键控制点

这些控制点保证快速生成不是无约束生成，云原生交付不是简单打包。

CONTROL 01

计划确认

需求、规范、代码基线和影响范围明确后才允许正式执行。

CONTROL 02

隔离执行

智能体只能在授权工作区、工具和资源预算内执行。

CONTROL 03

真实验证

以命令、测试、扫描或部署结果判断，不采信模型自述。

CONTROL 04

证据驱动推进

必需任务、产物、硬门禁、人工确认和证据齐备后才能推进阶段。

03

Functions

最后看功能：围绕快速生成和云原生交付组织能力

功能分为三组：快速生成能力解决“应用如何形成”，云原生交付能力解决“应用如何交付”，可信控制能力保障全过程可控、可验收、可追溯。

快速生成能力

完成需求理解、执行计划、智能体生成、测试配置协同生成和反馈修复。

主线前半段

云原生交付能力

完成镜像、部署资源、环境验证、回滚及在线或离线交付。

主线后半段

可信控制能力

通过项目规范、门禁、审批、风险接受和证据归档控制全过程。

贯穿全流程
01

项目规范与生成上下文

为快速生成提供受控技术栈、工程规范和最小上下文。

›

职责：承接技术栈、代码仓库、工程规范和交付要求，形成版本化项目规范与最小上下文包。

  • 维护工程结构、API、配置、日志、测试、安全、构建和交付规范。
  • 支持规范审核、发布、版本化和回滚。
  • 识别规范变更影响的未完成 Run、产物和交付基线。

验收重点

  • 每个 Run 绑定唯一规范版本。
  • 历史规范不可被覆盖。
  • 智能体只获得任务所需最小上下文和权限。
02

需求理解与生成目标判断

判断生成目标、工程等级、风险等级和交付目标。

›

职责：接收新建、变更和缺陷诉求，判断需求成熟度、工程等级、风险等级和交付方式。

  • 识别信息缺口和待澄清问题。
  • 按强制升级规则判断风险。
  • 支持接受或申请调整策略，并记录原因和审批。

验收重点

  • 不得仅以人数判断风险。
  • 触发强制升级时不得推荐低风险策略。
  • 每项推荐能够解释主要依据。
  • 不得自动编造业务规则和验收结论。
03

快速生成计划与人工确认

明确生成内容、验证策略、部署影响和风险后再执行。

›

职责：根据需求项、执行策略、项目规范和代码基线生成阶段化计划，并设置确认点、回退点和资源约束。

  • 支持计划编辑、版本对比、确认、驳回和重生成。
  • 单独标注接口、数据库、权限、配置和部署影响。
  • 关键输入变化时使旧确认自动失效。

验收重点

  • 生产级和标准以上风险未确认不得执行。
  • 存量变更包含代码基线、影响范围和回归策略。
  • 低置信假设必须显式展示。
04

智能体生成与任务执行

组织智能体在隔离工作区生成代码、测试、配置和部署资源。

›

职责：承接已确认计划，创建隔离工作区，分配智能体任务，采集过程并支持暂停、重试、接管和终止。

  • 任务绑定 Agent、Skill、模型、上下文和工具权限。
  • 采集会话、命令、文件差异、资源消耗和异常。
  • 设置超时、最大重试、token和资源预算。

验收重点

  • 不得写入授权工作区之外或直接改保护分支。
  • 失败、取消和超时形成明确状态及原因。
  • 修复超限后必须人工处理。
05

生成产物与版本管理

归集代码、测试、配置、镜像和部署资源并建立版本关系。

›

职责：记录智能体和人工产生的文件变化、生成说明、非生产项、风险标注及替代关系。

  • 产物关联需求、验收标准、Run、任务和代码版本。
  • 支持版本对比、废弃、撤回和替代。
  • 人工修改后重新评估受影响测试、门禁和确认。

验收重点

  • 生产级产物关联需求与验收标准。
  • 每次执行保留完整文件差异。
  • 原型必须包含非生产项清单。
  • 敏感信息不得写入产物。
06

自动验证与反馈修复

以真实构建、启动、测试和扫描结果驱动有限修复。

›

职责：执行构建、启动、测试、扫描和部署验证，形成硬/软门禁结果，分类失败并把证据反馈给智能体。

  • 门禁包含执行器、通过条件、超时、严重级别和证据类型。
  • 支持自动修复、人工修改后重验和阶段回退。
  • 风险接受绑定对象版本、责任人和有效期。

验收重点

  • 硬门禁失败不得交付。
  • 能区分环境、依赖、配置、代码、测试和权限问题。
  • 修复前后保留差异与验证证据。
07

镜像、部署资源与环境验证

形成云原生交付物并完成目标或等价环境验证。

›

职责：承接已通过门禁的产物，生成交付资源，调用工具链，执行环境预检、健康检查、冒烟测试和回滚，并锁定基线。

  • 记录镜像名称、标签、摘要、构建来源和日志。
  • 记录目标环境、部署状态、健康和访问验证。
  • 生产发布必须经过交付批准。

验收重点

  • 交付结果绑定需求、代码、规范和门禁。
  • 容器/K8s引用明确镜像版本或摘要。
  • 冒烟失败不得标记部署通过。
  • 基线不可原地覆盖。
08

离线交付分析、打包与验证

从已验证基线形成完整、可校验、可部署的离线交付单元。

›

职责：识别镜像、配置、端口、存储、证书和外部服务依赖，后续聚合镜像、资源、脚本、文档与校验和，并在隔离环境验证。

  • 阶段一只输出目录、清单、预检项和缺失项。
  • 真实包必须来自已验证交付基线。
  • 所有部署资源引用镜像必须包含在包内。

验收重点

  • MVP不得把“分析完成”宣称为“离线包可交付”。
  • 镜像、资源和配置版本一致。
  • 部署、验证和回滚资料完整。
09

分级门禁、评审与风险接受

根据风险控制审批、质量判定和交付授权。

›

MVP & Acceptance

第一阶段建设重点：先跑通一条快速生成到容器交付的闭环

第一阶段不追求覆盖所有技术栈和交付环境，而是在锁定技术栈上证明“需求输入—应用生成—真实验证—有限修复—容器交付—证据归档”能够稳定运行。

核心假设

Harness 能否将一个明确的低风险轻量需求，稳定转化为经过真实构建、启动和核心流程验证的可运行应用；失败时能否有限修复或正确请求人工接管。

第一阶段纳入

  • 单一项目规范与轻量需求入口。
  • 执行策略、计划确认和隔离工作区。
  • OpenCode执行与过程采集。
  • 构建、启动和核心流程冒烟测试。
  • 最多两轮自动修复与人工接管。
  • 轻量门禁、产物版本和基础证据。

第一阶段不纳入

  • 多技术栈和大型存量项目自动变更。
  • 完整生产门禁和复杂审批流。
  • Kubernetes真实自动部署。
  • 真实离线包、SBOM和供应链证明。
  • 复杂多智能体编排和自动生产发布。
